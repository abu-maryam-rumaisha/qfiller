# qfiller

qfiller is an **AST-based code generator for string templates**. It reads a
template string and generates Go source code (built with `go/ast`) that
rebuilds the string at runtime.

## Core idea

The generator splits a template into a sequence of **parts**. There are two
kinds:

| Kind         | Meaning                                       | In generated code                     |
|--------------|-----------------------------------------------|---------------------------------------|
| **Literal**  | Fixed text known when the code is generated   | A package-level `const`               |
| **Variadic** | A value only known at runtime                 | A `string` parameter of the function  |

## Template syntax

| Syntax   | Meaning                                                        |
|----------|----------------------------------------------------------------|
| `{name}` | Placeholder. `name` must be a valid Go identifier, not a keyword |
| `{{`     | A literal `{`                                                  |
| `}}`     | A literal `}`                                                  |

These templates are rejected with an error:
- an unclosed `{`
- a lone `}`
- an empty name, as in `{}`
- a name that isn't a Go identifier (`{1abc}`, `{a b}`) or is a keyword (`{func}`)

## Example

Template:

```text
Hello {name}, welcome to {place}!
```

Parts:

| # | Kind     | Value             |
|---|----------|-------------------|
| 1 | Literal  | `"Hello "`        |
| 2 | Variadic | `name`            |
| 3 | Literal  | `", welcome to "` |
| 4 | Variadic | `place`           |
| 5 | Literal  | `"!"`             |

Generated code (`-func Greet -pkg greet`):

```go
// Code generated by qfiller. DO NOT EDIT.

package greet

import "strings"

const (
	greetLit0 = "Hello "
	greetLit1 = ", welcome to "
	greetLit2 = "!"
)

func Greet(name, place string) string {
	var b strings.Builder
	b.Grow(20 + len(name) + len(place))
	b.WriteString(greetLit0)
	b.WriteString(name)
	b.WriteString(greetLit1)
	b.WriteString(place)
	b.WriteString(greetLit2)
	return b.String()
}
```

## Generation rules

- **Parameters** are listed in the order each placeholder first appears.
- **Repeated placeholders** share one parameter: `{x}-{x}` generates `func F(x string) string`.
- **Constant names** are `<funcName with lowercase first letter>Lit<N>`. If a
  name is already taken by a parameter of that function or by another
  top-level name, `_` is appended until it is unique.
- **Joining** uses a `strings.Builder`, sized up front with `Grow`: the
  literal byte count (worked out at generation time) plus `len` of each
  parameter, times the number of uses. The result is built with exactly one
  allocation. In `bench/`, this is about 20% faster than joining with `+`.
- **Edge cases**:
  - An empty template generates `return ""` and no constants.
  - A template with no placeholders generates a function with no parameters
    that returns its constant directly (no allocation).
  - A template that is a single placeholder, like `{v}`, returns the parameter
    directly.
- **Name clashes** with the builder code are avoided:
  - The builder variable is `b`, or `b_` (and so on) if a parameter or
    top-level name already uses it.
  - If `strings` is taken by a parameter or a top-level name, the package is
    imported under an alias such as `strings_`.
  - A placeholder named `{len}` would hide the builtin `len`, so its parameter
    is named `len_` instead. Arguments are passed by position, so callers are
    not affected.
- **Output** is run through `go/format` and starts with the standard
  `// Code generated ... DO NOT EDIT.` header.

## Templates in source comments

Instead of passing a template on the command line, you can write templates as
comments in Go source and let qfiller collect them with `-src`. Each
`//qfiller:FuncName` directive declares one function.

```go
package store

//go:generate qfiller -src . -o queries_gen.go

// One line: the template follows the function name.
//qfiller:QUser SELECT * FROM {schema}.users WHERE id = {id}

// Several lines: following line comments in the same group are joined with
// newlines (one space after // is stripped), up to the next directive.
//qfiller:QUserStores
// SELECT *
// FROM {schema}.users u
// INNER JOIN {schema}.store s ON s.user_id = u.id

/*qfiller:QCount
SELECT count(*)
FROM {schema}.users
*/
```

Rules:
- `-src` takes a `.go` file or a directory. In a directory, files are read in
  name order; `_test.go` files and generated files (such as the output of an
  earlier run) are skipped.
- All files must be in the same package. That package is used for the output
  unless `-pkg` is given.
- A block comment's template is everything after the function name, with
  leading newlines and trailing blank space removed.
- Comment lines before a directive are ignored, so you can describe a template
  in an ordinary comment above it.
- Put directives in their own comment, **not in a declaration's doc comment**:
  gofmt moves directive lines to the end of doc comments, which would separate
  the directive from its template. qfiller reports that case as "has no template".
- Errors (bad name, bad template, duplicate function name, no template) point
  at the source position, e.g. `queries.go:5:1: QUser: unclosed placeholder ...`.

## Usage

### CLI

```sh
go run . -template 'Hello {name}, welcome to {place}!' -func Greet -pkg greet -o greet_gen.go
go run . -src ./store -o ./store/queries_gen.go
```

| Flag        | Default | Description                       |
|-------------|---------|-----------------------------------|
| `-template` | SQL example | Template text (ignored with `-src`) |
| `-func`     | `QExample` | Name of the generated function (ignored with `-src`) |
| `-src`      |         | Go file or directory to read `//qfiller:` comments from |
| `-pkg`      | `main`, or the `-src` package | Package of the generated file |
| `-o`        | stdout  | Output file                       |

It can also be called from a `//go:generate` comment.

### Library

```go
import "qfiller/generator"

parts, err := generator.Parse("Hello {name}!")          // []generator.Part
pkg, specs, err := generator.Scan("./store")           // templates from //qfiller: comments
src, err := generator.Generate("greet",
	generator.Spec{FuncName: "Greet", Template: "Hello {name}!"},
	generator.Spec{FuncName: "Bye", Template: "Bye {name}."},
)                                                        // one file, several functions
```

## Layout

| Path                     | Contents                                            |
|--------------------------|-----------------------------------------------------|
| `main.go`                | CLI                                                 |
| `generator/parse.go`     | `Parse`: template → `[]Part` (Literal / Variadic)   |
| `generator/generate.go`  | `Generate`: parts → `go/ast` → formatted Go source  |
| `generator/scan.go`      | `Scan`: Go source → `[]Spec` from `//qfiller:` comments |
| `generator/*_test.go`    | Unit tests, plus an end-to-end test that compiles and runs the generated code |
| `bench/`                 | Benchmark of the generated code against `strings.ReplaceAll` |

## Testing

```sh
go test ./...          # includes the end-to-end test (needs the go tool)
go test -short ./...   # skips the end-to-end test
go test -bench . ./bench   # generated code vs strings.ReplaceAll
```
